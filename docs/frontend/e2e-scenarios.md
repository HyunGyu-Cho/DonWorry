# 시연 시나리오 흐름 기록 (1-13)

2026-10-26 · Issue #50 · Mock 모드(`VITE_USE_MOCK=true`) 기준

시연 시나리오 5개를 **돈워리를 처음 쓰는 사람**이 튜토리얼 안내만 보고 끝까지 따라가며 기록했다.
각 시나리오는 누르는 순서, 그 화면에서 확인할 것, 따라가다 걸려서 고친 것으로 적는다.
같은 흐름을 자동으로 누르는 테스트는 `frontend/e2e/scenarios.spec.ts`(Playwright)에 있다. 화면 폭 1440 · 1024 · 800px에서 모두 돌린다 (1-14).

## 0. 시작하는 법

- 랜딩(`/`)에서 시나리오를 고르면 `/login?scenario=N`으로 가고 아이디가 채워진다. 로그인하면 튜토리얼 카드가 자동으로 켜진다
- 시연 계정 (Mock)
  - 보안 직원 `jiwon` · 보안 관리자 `yunseo`: 비밀번호 1234 → OTP 246810
  - 사장님 `boss`: 비밀번호 1234 → 새 기기이거나 비밀번호를 5번 틀린 뒤면 이메일 확인 코드 135790
- 튜토리얼 카드
  - 해야 할 곳에 노란 테두리(`data-tour` 이름표)가 붙는다
  - 화면을 옮기면 다음 단계로 넘어간다. 판정 · 승인 · 세션 종료 · 차단 등록 같은 일은 그 일을 마치면 넘어간다
  - 카드가 노란 테두리 대상을 가리면 오른쪽 → 왼쪽 → 작은 버튼 순서로 비킨다
  - 마지막 단계의 [다음 시나리오]는 계정이 다르면 로그아웃 뒤 그 시나리오 로그인 화면으로 보낸다
- Mock 상태는 새로 고침하면 처음으로 돌아간다. 이어서 확인할 때는 주소창 대신 화면 안 링크로 옮긴다

## ① 결제 사기 의심 — 보안 직원 jiwon · 9단계

처음 쓰는 카드로 평소(4만 원)의 16배인 65만 원 결제가 들어온다.

1. 홈 `/security/home` — [확인할 결제 경보] 칸을 누른다
2. 결제 경보 `/security/alerts` — 김민수 · 65만 원 "직원 확인" 경보를 누른다
3. 경보 상세 `/security/alerts/103` — 55점 · 적중 Rule 2개(R01 고액 결제 +30 · R03 기존 결제 이력 없는 카드 +25, #96 룰 교체 뒤)를 보고 [사건 보기]
4. 사건 `/security/cases/201` — 흐름도에서 경보가 사건으로 묶인 것을 본다
5. 구매자 확인 — [구매자 화면 열기 ↗]로 구매자가 보는 화면(점수 · 이유 없음)을 보고, [구매자 답변 도착시키기 (시연)]
6. AI 재조사 — 단계가 하나씩 그려지고 v2 · 88점 "구매자가 결제하지 않았다고 답해 카드 도용 가능성이 높습니다"
7. AI 보고서 `/security/cases/201/report` — 결론 · 위험 근거 · 정상 정황 · 비슷한 과거 사건 · 경위, [AI가 조사한 과정] 탭
8. 판정 — 사건 화면에서 [승인 취소] + 사유 → [판정 확정] → 확인 창. 상태가 "조치 진행 중"으로 약 5초 머문 뒤 "종료"
9. 조치 센터 `/security/actions` — 승인 취소가 결제에 반영된 줄을 본다

따라가다 고친 것

- OTP 화면에 "246810은 어디서 받나" 안내가 없었다 → 실제로는 휴대폰 인증 앱의 30초마다 바뀌는 6자리, 시연에서는 고정 코드라고 OTP 화면에 적음
- 숫자가 화면마다 달랐다(평소의 5배 · 16배) → "평소(4만 원)의 16배 · 기준 5배 이상". 5배는 Rule 기준이고 실제 배수는 평가 당시 값
- 화면을 옮겨도 스크롤이 아래에 남았다 → 화면 이동 시 맨 위로 (내용이 늦게 그려져도 한 번 더)
- 시각이 앞뒤가 안 맞았다(사건이 결제보다 먼저) → Mock 시각을 결제 → 경보 → 사건 순서의 고정 기준 시각(`mockEpoch`)에서 만듦
- v2 보고서에 v1 내용("구매자 응답 아직 없음", "본인 확인 연락" 권고)이 남았다 → v2에 맞게 바꿈
- 판정하자마자 "종료"가 돼 조치 단계를 볼 수 없었다 → Mock 조치가 약 5초 "조치 진행 중"으로 머문 뒤 반영 (현규 결정 A)
- 튜토리얼 카드가 [판정 확정] 버튼과 확인 창을 가렸다 → 대상과 겹치면 비키고, 카드는 확인 창 아래 층으로
- 판정해도 튜토리얼이 그대로였다 → 판정 확정하면 다음 단계로

## ② 직원 계정 분산 공격 — 보안 관리자 yunseo · 6단계

IP 30곳에서 1~3번씩 로그인을 시도해 직원 계정들을 노린다. IP마다 세면 걸리지 않고, 계정 기준으로 묶어야 보인다.

1. 홈 `/manager/home` — [의심 사건] 칸을 누른다 (칸: 승인 대기 · 의심 사건 · 감사 로그)
2. 의심 사건 (직원 계정) `/manager/cases` — "직원 계정 2개 (박지원 · 이도현)" 사건을 누른다
3. AI 실시간 조사 `/manager/cases/102` — 약 15~20초. 중간에 "⚠ 1차 판단 실패 → 다시 시도"가 보인다. 끝난 뒤에도 [조사 과정 다시 보기]로 펼칠 수 있다
4. 흐름도 — 경보 2장(패스워드 스프레이 · 분산 무차별 대입)이 사건 1건으로 묶인다
5. AI 보고서 — [AI가 조사한 과정] 탭에서 "x초부터 · y초 걸림"으로 단계별 시간을 본다
6. 로그인 모니터링 `/manager/access` — [계정별로 묶어 보기]를 누르면 흩어진 IP 30개가 박지원 · 이도현 계정으로 모인다

따라가다 고친 것

- 관리자 홈 칸 이름이 처음 보는 사람에게 어려웠다 → "승인 대기 · 의심 사건 · 감사 로그(확인 필요 N건)" + 칸 아래 한 줄 설명 (현규 결정)
- Rule 이름 "비밀번호 뿌리기 · 분산 로그인 실패" → "패스워드 스프레이 · 분산 무차별 대입". 영어 원어는 Rule 카탈로그에만 (현규 결정 A, 서버 시드 이름은 P2가 2단계에서 맞춤)
- 메뉴 "직원 접속 감시" → "로그인 모니터링" (감시는 직원을 지켜보는 느낌, 실무 용어는 모니터링). 분산 공격이 왜 문제인지 화면에 쉬운 설명을 붙임
- 실시간 조사가 7초 만에 끝나 실패 → 재시도를 볼 틈이 없었다 → 약 15~20초, 실패 단계에서 잠깐 멈춤 (현규 결정 A)
- 숫자가 화면마다 달랐다(실패 40회 · 41회, IP당 1~2번 · 1~3번) → Mock 숫자를 한 곳에서 만듦 (IP 30 · 41회 · 1~3번)
- 카드가 왼쪽 · 오른쪽 모두 대상을 가리면 → 작은 버튼으로 접음

- 멘토 질문 "주문이 수십 건이면 캘린더에 어떻게 보이나" → 칸에는 합계만, 날짜를 누르면 옆 창 목록(상태 필터 · 검색), 전체 페이지로도 볼 수 있게 (현규 결정)

## ⑤ 카드 테스팅 → 자동 차단 — 보안 직원 jiwon · 4단계

짧은 시간에 여러 카드로 결제를 시도해 쓸 수 있는 카드를 찾는다. 80점 이상이라 사람을 기다리지 않고 바로 거절됐다 (#96 룰 교체 뒤 기준).

1. 홈 `/security/home` — 왼쪽 [결제 경보]
2. 결제 경보 `/security/alerts` — 정하늘 · 1만 2,000원 "거절" 경보
3. 경보 상세 `/security/alerts/106` — 85점 · 적중 Rule 2개(R06 카드 테스팅 +45 · R05 고위험 국가 IP +40, #96 룰 교체 뒤). [차단 목록에 등록] → 추천 값(카드 · 기기 · 이메일)이 미리 골라져 있고 IP는 "주의 · 여러 명이 같이 씀". 사유를 적고 등록
4. 차단 목록 `/security/blocklist` — 방금 등록한 줄에 `방금 등록`, 막은 결제가 없으면 "아직 막은 결제 없음"

따라가다 고친 것

- 가입 40분 된 계정인데 "평소 쓰던 카드 · 평소와 비슷한 금액" → "이전 결제가 없어 비교할 수 없어요" (➖)
- 자동화 브라우저 기기가 ✅로 보였다 → ⚠
- 차단 등록 창에서 무엇을 골라야 할지 몰랐다 → 추천 · 주의 태그, 추천은 미리 체크
- 등록해도 표시가 없고 튜토리얼이 그대로였다 → "차단 N건 등록됨 ✓", 등록하면 다음 단계로
- 사건 상태 "인계 대기 · 인계 실패" → "조치 진행 중 · 조치 실패" ("판정 대기"는 이미 다른 상태라 겹치지 않게, 현규 결정)
- 튜토리얼 안내 "90점 이상은 바로 거절" → 실제 기준 "70점 이상"
