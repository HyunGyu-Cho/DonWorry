# 시연 켜는 법 (처음 켜는 사람용)

돈워리 시연은 서버 3개를 켭니다: **백엔드(Spring) · AI 서버(ai-server) · 화면(frontend)**.
설정은 폴더마다 `.env` 파일 하나에 둡니다. 창마다 환경 변수를 칠 필요가 없습니다 (#84).

## 0. 준비

- MariaDB가 3307에서 돌고 있어야 합니다 (README 2절). 개인용 DB 이름을 쓰면 1번에서 `DONWORRY_DB_NAME`을 바꿉니다
- `uv` · `node`가 설치돼 있어야 합니다 (README 사전 준비)

## 1. 설정 파일 만들기 (처음 한 번)

예시 파일을 복사합니다. `.env`는 git에 올라가지 않습니다.

```powershell
copy backend\.env.example backend\.env
copy ai-server\.env.example ai-server\.env
copy frontend\.env.example frontend\.env
```

그다음 **서비스 키 하나를 정해 두 곳에 똑같이** 적습니다. 아무 문자열이면 됩니다 (예: 내가 정한 긴 단어).

```
backend/.env    DONWORRY_AI_SERVER_SERVICE_KEY=내가-정한-키
ai-server/.env  AI_SERVER_SERVICE_KEY=내가-정한-키
```

- 백엔드와 AI 서버가 서로를 알아보는 암호입니다. 둘이 다르면 사건 화면에 "AI 조사에 실패했어요"가 뜹니다
- 개인용 DB · 다른 비밀번호를 쓰면 `backend/.env`의 `DONWORRY_DB_NAME` · `DONWORRY_DB_PASSWORD`를 바꿉니다

> **예전 방식 `application-local.yml`을 쓰고 있었다면** 이제 그 파일은 읽지 않습니다.
> 그 안의 DB 이름 · 비밀번호를 `backend/.env`의 `DONWORRY_DB_NAME` · `DONWORRY_DB_PASSWORD`로 옮기고, 옛 파일은 지워도 됩니다.

예시 그대로 두면 이렇게 켜집니다.

| 설정 | 값 | 뜻 |
| --- | --- | --- |
| `DONWORRY_REPORT_WRITER` | `ai-server` | AI 조사를 AI 서버에 맡김 |
| `DONWORRY_CARD_COMPANY_DELAY` | `PT5S` | 판정 뒤 "조치 진행 중" 5초 |
| `DONWORRY_DEMO_FAKE_CLIENT_IP` | `true` | 테스트 상점 "접속 환경"(국내 · 새 휴대폰 · 해외 VPN · Tor)을 결제창이 믿음. 운영은 `false` (#98) |
| `DONWORRY_REPORT_RESULT_TIMEOUT` | `PT5M` | AI 조사 결과를 5분까지 기다림 (진짜 AI는 몇 분 걸림) |
| `AI_SERVER_LLM_PROVIDER` | `mock` | 가짜 AI가 보고서를 씀 — 진짜 AI는 4절 |
| `AI_SERVER_MOCK_DELAY_SECONDS` | `1` | 가짜 AI가 단계마다 1초 쉼 → 조사 과정이 한 줄씩 보임 |
| `VITE_USE_MOCK` | (비움) | 화면이 실제 API를 씀 |

## 2. 켜기 (창 3개)

```powershell
# 창 1
cd backend
.\gradlew.bat bootRun

# 창 2
cd ai-server
uv sync
uv run uvicorn app.main:app --port 8000

# 창 3
cd frontend
npm install
npm run dev
```

창 1에 `Started DonWorryApplication`, 창 2에 `Application startup complete`가 보이면 준비됐습니다.

## 3. 시나리오 ① 결제 사기 의심

1. 새 탭에서 `http://localhost:5173/demo/shop` → **단체 행사용 케이크 세트(65만 원)** [결제하기] → **처음 쓰는 카드** → "결제가 완료되었습니다" (뒤에서는 매입 보류 · 직원 검토, #86)
2. `http://localhost:5173/login`에서 `jiwon` / `1234` 로그인
3. 홈 → [확인할 결제 경보] → 김민수 · 65만 원 경보 → [사건 보기]
4. 사건 화면 [구매자 화면 열기 (시연)] → 새 탭에서 "아니요, 결제하지 않았어요"
5. 사건 화면으로 돌아오면 AI가 v2로 다시 조사하는 과정이 한 줄씩 그려집니다
6. [AI 보고서]에서 결론 확인 → 사건 화면에서 [승인 취소] + 사유 → [판정 확정]
7. "조치 진행 중" 약 5초 뒤 "종료" → 조치 센터에서 반영 확인

> **비슷한 과거 사건 (#104):** 보고서의 "비슷한 과거 사건"은 판정이 끝난 사건에서 찾습니다. DB를 새로 만든 뒤 첫 시연에서는 "비슷한 과거 사건이 없어요"가 정상입니다. 보여 주려면 시연 전에 위 1~7번을 한 번 끝까지 해 두세요 (리허설). 다음 시연부터 같은 고객 · 같은 카드로 들어온 사건이 "강하게 비슷 · 사기 확정"으로 잡힙니다.

## 3-1. 시나리오 ⑤ 카드 테스팅 → 차단 따라 하기 (#100)

`backend/.env`의 `DONWORRY_DEMO_FAKE_CLIENT_IP=true`가 켜져 있어야 "접속 환경"이 적용됩니다.

1. 새 탭에서 `http://localhost:5173/demo/shop` → **구매자: 처음 온 손님** · **접속 환경: 해외 VPN**
   - 처음 온 손님은 탭마다 새 손님 번호가 생깁니다 (결제 이력 없음). 김민수(단골)로 하면 첫 결제부터 거절돼 장면이 안 나옵니다
2. 아무 상품 [결제하기] → **도난 카드 1** → 결제 완료 (해외 VPN 40점 · 통과)
3. 같은 탭에서 다시 [결제하기] → **도난 카드 2** → 카드사 거절(분실 · 도난) → 한 번 더 → **도난 카드 3** → 결제 불가. 이번엔 카드사까지 가지 않고 돈워리가 막습니다 (1시간에 카드 3장 = 카드 테스팅 45 + 해외 VPN 40 + 10분에 3번 30 → 80점 이상 자동 거절)
4. `http://localhost:5173/login`에서 `jiwon` / `1234` → [결제 경보] → "처음 온 손님"의 **거절** 경보
5. 적중 Rule을 보고 [차단 목록에 등록] → **기기만** 고르고 사유 입력 → 등록
6. 결제한 탭으로 돌아가 [결제하기] → **도난 카드 5** → 점수 계산 없이 바로 막힘 (차단 목록 100점)
7. [차단 목록]에서 방금 등록한 기기 · 막은 결제 수 1 확인

> **다시 하려면 새 탭**(또는 테스트 상점의 [새 손님으로 바꾸기])에서 시작합니다. 손님마다 기기 값이 달라 방금 막은 기기와 겹치지 않습니다.
> 카드 · IP · 이메일까지 막으면 다음 시연의 첫 결제부터 막힙니다. 이때는 아래 3-3절처럼 관리자 승인으로 풉니다 (#104).

## 3-3. 차단 해제 · Rule 끄기는 관리자 승인 뒤에 반영 (#104)

차단을 풀거나 Rule을 끄면 탐지가 약해지므로 보안 직원이 요청하고 보안 관리자가 승인해야 실제로 바뀝니다. 다시 켜는 것은 승인 없이 바로 됩니다.

1. `jiwon` / `1234` → [차단 목록] → 3-1절에서 등록한 기기의 [해제 요청] → 사유 입력 → 요청
   - 승인 전에는 그대로 막혀 있습니다. 결제한 탭에서 다시 결제해 보면 여전히 바로 막힙니다
2. 로그아웃 → `yunseo` / `1234` → [승인함]에서 "차단 해제" 요청 [승인]
3. 결제한 탭으로 돌아가 [결제하기] → 이번에는 차단 목록과 대조하지 않고 점수로만 판단합니다 (해외 VPN 40점 등)
4. Rule 끄기도 같습니다: `jiwon` → [Rule 카탈로그] → 결제 Rule(R01~R06 · R08)의 [끄기 요청] → `yunseo`가 승인하면 다음 결제부터 그 Rule은 점수를 더하지 않습니다
   - R07 차단 목록 · 직원 Rule은 끄기 요청을 받지 않습니다
5. 꺼진 Rule은 `jiwon`이 [다시 켜기]로 바로 켭니다
6. `yunseo`의 [감사 로그]에서 차단 해제 반영 · Rule 끄기 반영(처리자 = 승인한 관리자) · Rule 다시 켜기가 한 줄씩 남은 것을 확인

> 요청한 뒤 다른 경로로 이미 꺼졌거나 풀렸다면 승인은 처리되지만 아무것도 바뀌지 않고, 감사 로그에 "이미 꺼져 있음 · 이미 풀려 있음"이 남습니다.

## 3-2. AI 권고와 반대로 판정 → 관리자 승인 (#102)

3절 시나리오 ① 6번에서 [승인 취소] 대신 이렇게 해 봅니다. 가짜 AI(`AI_SERVER_LLM_PROVIDER=mock`)는 65만 원 결제에 "승인 취소 검토"를 권고합니다.

1. `jiwon`으로 사건 화면 → 결제에서 **[매입 허용]** + 사유 → [재인증 후 승인 요청]
2. "비밀번호 다시 확인" 창에 `1234` → 사건이 **관리자 승인 대기**가 되고 결제는 그대로(매입 보류)
3. 로그아웃 → `yunseo` / `1234` 로그인 → [승인함]에서 요청을 [승인] (또는 이유를 적고 [거절])
4. 승인하면 박지원 이름으로 판정이 반영돼 매입이 진행되고, 거절하면 사건이 판정 대기로 돌아갑니다
5. `yunseo`의 [감사 로그]에서 로그인 · 승인 요청 · 승인 · 판정이 한 줄씩 남은 것을 확인

> 비밀번호를 5번 연속 틀리면 그 계정은 30분 동안 잠깁니다. 시연 중 잠겼다면 30분을 기다리거나, 시연용 DB에서만 `UPDATE platform_users SET locked_until = NULL, failed_login_count = 0 WHERE login_id = 'jiwon';`

## 4. 진짜 AI(Ollama Qwen)로 바꾸기 (#88)

가짜 AI는 정해진 순서로 증거를 보고 보고서를 조립합니다. 진짜 AI는 **어떤 증거를 볼지 스스로 고르고** 보고서를 직접 씁니다.
내 PC 안에서만 돌아가서 결제 · 고객 정보가 밖으로 나가지 않습니다.

1. [ollama.com](https://ollama.com)에서 Windows용 Ollama를 설치합니다 (설치하면 작업 표시줄에서 계속 켜져 있음)
2. 증거가 잘리지 않게 문맥 길이를 늘립니다 — PowerShell에서 한 번만, 그다음 Ollama를 껐다 켭니다
   ```powershell
   setx OLLAMA_CONTEXT_LENGTH 8192
   ```
3. 모델을 받습니다 (약 4.7GB, 처음 한 번)
   ```powershell
   ollama pull qwen2.5:7b
   ```
4. `ai-server/.env`에서 한 줄을 바꾸고 AI 서버(창 2)를 다시 켭니다
   ```
   AI_SERVER_LLM_PROVIDER=ollama
   ```
5. 시나리오 ①을 그대로 합니다. 조사 과정에 "AI 판단 — 다음에 볼 증거 고르기"가 AI가 고른 만큼 보입니다

알아 둘 것

- **"근거 검사 실패 → 다시 시도"도 정상:** AI가 받은 증거에 없는 숫자 · 출처를 쓰면 틀린 곳을 짚어 다시 쓰게 합니다 (#92). "받고도 안 쓴 증거"는 알림일 뿐 실패가 아닙니다
- **"구조 검증 실패 → 다시 시도"가 한 번 보이는 건 정상:** 작은 모델은 보고서 모양을 가끔 틀립니다. 2차부터는 모양을 고정해 물어서 대부분 통과합니다. 3번 모두 틀리면 바로 "AI 조사에 실패했어요" → [AI 조사 다시 하기] 또는 직접 판정
- **시간:** 그래픽카드 없이 CPU로 돌면 보고서 1건에 2~4분 걸립니다. 너무 느리면 `ollama pull qwen2.5:3b` 후 `AI_SERVER_LLM_MODEL=qwen2.5:3b` (빠르지만 형식을 더 자주 틀림 → "AI 판단 (2차)"로 다시 물음)
- **포트:** Ollama는 내 PC 안(`127.0.0.1:11434`)에서만 받습니다. `OLLAMA_HOST`를 `0.0.0.0`으로 바꾸지 않습니다 (같은 와이파이의 누구나 쓸 수 있게 됨)
- **OpenAI로 바꾸기:** `AI_SERVER_LLM_PROVIDER=openai`, `AI_SERVER_LLM_MODEL=gpt-4o-mini`, `AI_SERVER_LLM_API_KEY=`에 키를 직접 넣습니다. 키는 저장소 · 메신저에 붙여 넣지 않습니다
- **되돌리기:** `AI_SERVER_LLM_PROVIDER=mock`

## 자주 겪는 문제

- **사건 화면 "AI 조사에 실패했어요"** — 서비스 키가 두 `.env`에서 다르거나, AI 서버(창 2)가 꺼져 있습니다. 키를 맞추고 두 서버를 다시 켠 뒤, 사건 화면 [AI 조사 다시 하기]를 누릅니다
- **조사 과정에 "AI 호출 실패: AI 서버 연결 실패"** — Ollama가 꺼져 있습니다. 작업 표시줄에서 Ollama를 켜고 [AI 조사 다시 하기]
- **"AI 서버 오류 404: model ... not found"** — 모델을 아직 받지 않았거나 `.env`의 모델 이름이 다릅니다. `ollama list`로 이름을 확인합니다
- **"AI 응답 시간 초과"** — 모델이 너무 느립니다. 3b 모델로 바꾸거나 `AI_SERVER_LLM_TIMEOUT_SECONDS`를 늘립니다 (늘리면 `DONWORRY_REPORT_RESULT_TIMEOUT`도 함께)
- **`Port 8081 was already in use`** — 이미 켜진 백엔드가 있습니다. 그 창을 닫거나 `Ctrl+C`로 끕니다
- **`.env`를 고쳤는데 그대로** — 설정은 켤 때만 읽습니다. 그 서버를 껐다 켭니다
- **값을 비워 둔 줄** — `KEY=`처럼 남기면 "빈 값"이 됩니다. 안 쓸 줄은 지우거나 앞에 `#`을 붙입니다
- **테스트는 `.env`를 읽지 않습니다** — 내 PC 설정이 테스트 결과를 바꾸지 않게 막아 두었습니다
