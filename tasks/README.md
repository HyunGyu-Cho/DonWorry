# tasks

**여러 세션에 걸치는 복잡한 작업의 실행 맥락**만 남긴다.

여기에 두지 않는 것:

- 담당·우선순위·목표·진행 상태 → **GitHub Issue**
- 설계 결정과 그 이유 → `docs/decisions/`
- 업무 정책 → Notion

한두 세션에 끝나는 작업은 TASK 파일을 만들지 않는다. Issue와 커밋으로 충분하다.

## 규칙

- 파일명 `TASK-###.md`, 번호는 3자리 연번.
- 대응하는 GitHub Issue를 본문에 링크한다. 목표를 여기에 다시 쓰지 않는다.
- **체크박스를 믿지 않는다.** 완료 표시는 코드·Git·검증 결과로 대조한다 (Notion 06-2).
- 기록할 시점: 작업 착수, 의미 있는 기능 완료, 테스트 결과, 설계 변경, 작업 전환.
- 작업이 끝나면 파일을 지우지 말고 "완료" 상태로 둔다. 다음 사람이 경로를 되짚을 수 있어야 한다.
- 템플릿: [`TASK-000-template.md`](TASK-000-template.md)

## 주의

자동 저장이나 종료 시 기록은 보장되지 않는다. 훅을 아직 만들지 않았다 (CLAUDE.md).
남겨야 할 것은 직접 커밋한다.
